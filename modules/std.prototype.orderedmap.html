Module std.prototype.orderedmap

Ordered Map Prototype.

This module returns a table of ordered map operators, as well as the prototype for an OrderedMap container object.

An OrderedMap is a table that remembers the order in which its keys were first added. Fields are read and written as for any table, and a new key goes to the end, while writing the value of a key that is already there keeps it in its place.

A map is not a list and it has no length: # and len give the length of the sequence part of its fields, not the number of actual keys. Count the keys with size.

To remove a key, use delete. The remaining keys keep their order, and a key that is appended again is put at the end. Writing nil to a field or using rawset bypasses the OrderedMap metadata bookkeeping leaving stale keys until updated by appending again or the whole map is copied.

A key can be any value but nil, and its value can be any value but nil. While the entries are the fields of the object itself, the entry order is held in the metatable of each object.

Write the entries of a new map as a list of tables of one pair each:

local OrderedMap = require 'std.prototype.orderedmap'.prototype
local build = OrderedMap {{core = 'core.c'}, {util = 'util.c'}}
build.extra = 'extra.c'
for name, source in elems(build) do
   print(name, source)      --> core core.c, util util.c, extra extra.c
end

In addition to the functionality described here, OrderedMap containers also have all the methods and metamethods of the prototype.container.prototype (except where overridden here).

Metamethods

__call (t)
OrderedMap object initialisation.

Returns a new OrderedMap with the entries of this one, and then those of the list t of tables of one pair each, in order; where a key is written more than once the last value replaces the first, in place. A field of t that is named with a leading underscore, such as _type, is a field of the metatable instead, its n field, as entries makes, is ignored, and any other is an error.

A type that is derived with an _init function is called with the new map, which has the entries of the one called, and then all the arguments, as Container's _init is, in place of all that, and returns the map. As for Container, deriving another type from one with an _init calls it with the table that describes the new type, so it must handle fields that start with an underscore.

Parameters:

  • t table entries, and fields of the metatable

Returns:

    OrderedMap a new map

Usage:

    local build = OrderedMap {{core = 'core.c'}, {util = 'util.c'}}
local Config = OrderedMap {_type = 'Config', _init = function(new, name)
   new.name = name
   return new
end}
local config = Config 'demo'
